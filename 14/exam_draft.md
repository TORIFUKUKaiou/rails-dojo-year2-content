### 🗄️ テーマ1：データベース設計とアソシエーション（問1〜問5）

#### 問1
1人のユーザー（User）が複数の記事（Article）を投稿できる「1対多（`has_many` / `belongs_to`）」の関係をRailsで構築します。このとき、データベース上で外部キー（ `user_id` ）を追加すべきなのはどちらのテーブルですか？
1. `users` テーブル
2. `articles` テーブル
3. 両方のテーブル
4. 外部キーを置く必要はなく、新しく中間テーブルを作成する

<details>
<summary>解答・解説</summary>

* **解答**：2
* **解説**：1対多の関係では、「多（子）」の側である `articles` テーブルに、親を識別するための外部キー `user_id` を配置します。

</details>

#### 問2
既存の `articles` テーブルに、記事の公開日時を記録するための `published_at` カラム（日時型：`datetime`）を追加するマイグレーションを作成したいです。`change` メソッド内に記述すべき適切なRailsのコードはどれですか？
1. `add_column :published_at, :articles, :datetime`
2. `add_column :articles, :published_at, :datetime`
3. `create_column :articles, :published_at, :timestamp`
4. `add_field :articles, :published_at, :date`

<details>
<summary>解答・解説</summary>

* **解答**：2
* **解説**：カラム追加の基本構文は `add_column :テーブル名, :カラム名, :データ型` です。

</details>

#### 問3
アソシエーション `belongs_to :user` を `Article` モデルに定義したとき、Railsが自動的に提供する機能（メソッド）として**誤っているもの**はどれですか？
1. `@article.user` で、その記事を投稿したユーザー情報を取得できる。
2. `@article.user = @user` で、記事の投稿ユーザーを紐付けられる。
3. `@article.build_user` で、紐付いた新しいUserオブジェクトをメモリ上に生成できる。
4. `@article.users` で、この記事に関連する複数のユーザー一覧を配列で取得できる。

<details>
<summary>解答・解説</summary>

* **解答**：4
* **解説**：`belongs_to` は単一の親との紐付けを定義するため、取得できるのは単一のオブジェクトです。複数形（`@article.users`）で取得できるのは `has_many` が定義されている場合です。

</details>

#### 問4
データベース設計において、テーブルに「主キー（Primary Key）」を設定する最大の目的は何ですか？
1. テーブル内のレコードを重複なく、一意に（ユニークに）識別するため。
2. テーブル間の接続関係（アソシエーション）をRailsに教えるため。
3. レコードの作成日時（`created_at`）を自動で保存するため。
4. データベースの検索速度を制限するため。

<details>
<summary>解答・解説</summary>

* **解答**：1
* **解説**：主キーは、テーブル内の各行（レコード）を絶対に重複せずに一意に識別するための最も重要なID列です。

</details>

#### 問5
データベースの「ロールバック（ `bin/rails db:rollback` ）」を実行した際のRailsの挙動として、正しいものはどれですか？
1. データベースの全テーブルを一度に削除し、初期状態にする。
2. 最後に実行されたマイグレーションファイルの変更内容を打ち消し、1つ前の状態に戻す。
3. 下書き状態の記事データをすべて本番データベースへ反映する。
4. アプリケーションコードのエラーを自動的に修正する。

<details>
<summary>解答・解説</summary>

* **解答**：2
* **解説**：`db:rollback` は、直前に実行されたマイグレーションの `change`（または `down`）を実行し、スキーマの状態を1つ前のバージョンに戻すコマンドです。

</details>

### 🌐 テーマ2：MVC構造とHTTPリクエスト（問6〜問10）

#### 問6
ユーザーがブラウザで「記事の新規登録フォーム」を入力し、送信ボタン（POST）を押しました。Railsアプリがデータを受け取ってから、データベースに保存し、完了画面（記事一覧など）へリダイレクトしてブラウザに表示するまでの内部処理の流れとして、最も適切な順序はどれですか？
1. `Routing ➔ Controller (create) ➔ Model (save) ➔ Controller ➔ Redirect (index) ➔ Routing ➔ Controller (index) ➔ View`
2. `Routing ➔ View ➔ Controller (create) ➔ Model (save) ➔ Redirect (index)`
3. `Controller (create) ➔ Routing ➔ Model (save) ➔ View ➔ Redirect (index)`
4. `Routing ➔ Controller (create) ➔ View ➔ Model (save) ➔ Redirect (index)`

<details>
<summary>解答・解説</summary>

* **解答**：1
* **解説**：POSTリクエストの処理完了後は、二重送信を防ぐためにブラウザに「リダイレクト（別のURLへアクセスし直させる指示）」を返します。そのため、再度ルーティングを経由してGETリクエストが走り、Viewが表示されます。

</details>

#### 問7
`config/routes.rb` に `resources :articles` と定義されているとき、特定の記事（ID: 5）の「編集画面（フォーム画面）」を表示するために、ブラウザが送信すべき「HTTPメソッド」と「URL（パス）」の正しい組み合わせはどれですか？
1. `GET` / `/articles/5/edit`
2. `POST` / `/articles/5/edit`
3. `PATCH` / `/articles/5`
4. `GET` / `/articles/edit/5`

<details>
<summary>解答・解説</summary>

* **解答**：3
* **解説**：記事の編集用フォーム画面をGETで要求するURLは `/articles/:id/edit` になります（PATCHは編集内容を送信する際のアクションです）。

</details>

#### 問8
Railsのコントローラーで、フォームから送信されたデータ（パラメータ）を安全に受け取るための仕組みである「Strong Parameters」において、`params.require(:article).permit(:title, :content)` と書きました。このコードが意味する内容として正しいものはどれですか？
1. パラメータに `article` キーが必須であり、その中の `title` と `content` のみの変更を許可する。
2. `title` と `content` の入力を必須とし、未入力の場合はエラー画面を表示する。
3. `article` というテーブルを新規作成し、そこに `title` と `content` というカラムを追加する。
4. データベースへの保存を一時的に禁止し、データを暗号化する。

<details>
<summary>解答・解説</summary>

* **解答**：1
* **解説**：`require` は指定したキーがパラメータに含まれているかを検証し、`permit` は指定したカラム以外の不正なデータ（悪意ある書き換え）をフィルタリングして安全にデータベースへ保存できるようにします。

</details>

#### 問9
Railsのビュー（View）ファイルで使われる `<%= @article.title %>` と `<% @article.title %>` の違いについて、正しい説明はどれですか？
1. `<%= %>` は計算処理を行うだけで、`<% %>` は結果を画面に出力する。
2. `<%= %>` は処理の結果を画面に出力するが、`<% %>` は処理を実行するだけで画面には出力しない。
3. `<%= %>` はデータベースにデータを保存し、`<% %>` はデータを読み出すだけである。
4. 両者に違いはなく、どちらを使っても画面に出力される。

<details>
<summary>解答・解説</summary>

* **解答**：2
* **解説**：`=` が付くタグは評価した結果の文字列をHTMLに埋め込み（出力）しますが、`=` が付かないタグは、`if`文や`each`ループなどの制御構文の実行時に使用され、出力は行いません。

</details>

#### 問10
Railsのコントローラーアクション内で `redirect_to articles_path` と `render :index` を実行した際の違いについて、正しい説明はどれですか？
1. `redirect_to` はブラウザに新しいURLへアクセスし直すよう指示し、`render` はURLを変えずに指定したViewファイルをその場で表示する。
2. `redirect_to` は画面を表示するだけで、`render` はデータベースのデータをすべて削除する。
3. `redirect_to` は処理を即座に終了し、`render` は別のアクションの処理を最初から実行する。
4. 両者は全く同じ挙動であり、使い分ける必要はない。

<details>
<summary>解答・解説</summary>

* **解答**：1
* **解説**：`redirect_to` はHTTPレスポンスの 302（一時的移動）を返し、ブラウザに新しいリクエスト（GET）を再送させます。`render` は現在のリクエスト処理の中で、指定したテンプレートのHTMLを直接作成して返します。

</details>

#### 問13

#### 問14

1. これらの記号は削除せず、そのままファイルを保存して `git push` する。
2. 記号で囲まれた部分を比較し、残したいコードに手動で書き換え、記号（マージマーカー）自体はすべて削除した上で `git add` および `git commit` を実行する。

<details>
<summary>解答・解説</summary>

* **解説**：マージマーカーは衝突箇所を示す印です。競合箇所を人の目で判断してコードを整理し、これらのマーカー記号はすべてきれいに削除した状態でステージングしてコミットします。

</details>

AWS上に作成したEC2インスタンス（Railsアプリが動いている）への直接のアクセス（ポート3000番）を遮断し、「ALB（ロードバランサー）から来た通信のみ」を許可するように設定を変更したいです。EC2用セキュリティグループのインバウンドルールの「ソース（送信元）」には、何を指定するのが最も安全ですか？

### 🚨 テーマ5：本番起動とエラーデバッグ（問19〜問20）

#### 問19
EC2上のRailsアプリを `production` モードで起動し、ALBのDNS名からブラウザでアクセスしたところ、「画面は表示されたが、CSSのデザインが一切適用されず、白黒の骨組みだけの画面」になってしまいました。この原因と対策として最も適切なものはどれですか？
1. データベースのマイグレーションが実行されていないため、データベースをリセットする。
2. production用の「アセットプリコンパイル（`assets:precompile`）」が実行されておらず、アセットファイルが生成されていない。対策として、アセットをコンパイルし、静的ファイル配信（`RAILS_SERVE_STATIC_FILES=true`）を有効にして再起動する。
3. EC2インスタンスのCPUスペックが不足しているため、インスタンスタイプを大きくする。
4. ドメインのDNS設定が間違っているため、Route 53の設定を初期化する。

<details>
<summary>解答・解説</summary>

* **解答**：2
* **解説**：productionモードでは、動作速度を上げるためにCSS/JSを事前にビルド（アセットプリコンパイル）しておく必要があります。また、Puma（Rails）単体で動かす場合は、静的ファイルの配信設定を明示的に有効にしなければCSSファイルをブラウザに返せません。

</details>

#### 問20
Railsアプリを `production` モードで起動しようとした際、ターミナルに「`ActiveRecord::ConnectionNotEstablished` (データベースへの接続に失敗しました)」というエラーが出力され、起動に失敗しました。このトラブルを解決するために確認・修正すべき内容として、最も可能性が高いものはどれですか？
1. `SECRET_KEY_BASE` が設定されていないため、適当な値を設定する。
2. 環境変数 `DATABASE_URL` に指定している「RDSのendpoint」や「ユーザー名」「パスワード」が正しいか確認し、設定し直す。
3. AWSコンソールでS3バケットを新規作成し、バケット名を設定ファイルに書き込む。
4. `routes.rb` の定義に誤りがないか確認し、ルーティングを追加する。

<details>
<summary>解答・解説</summary>

* **解答**：2
* **解説**：`ConnectionNotEstablished` などのDB接続エラーは、データベースの接続文字列（環境変数 `DATABASE_URL`）の記述ミス、またはRDS側のセキュリティグループでEC2からの通信（ポート5432番）が拒否されている場合に発生します。

</details>

## 🏁 第2部：実技試験「本番デプロイ・タイムアタック」

### 🎯 ミッション要件
制限時間内に、開発環境（Codespaces）でアプリに指定のカスタマイズを加え、自分自身のGitHubを経由して、AWS上に「ALB ➔ EC2 2台 ➔ RDS」のマルチAZ高可用性環境を構築し、アプリを正常にデプロイしなさい。

#### 【条件】
- 講義資料、過去のソースコード、インターネット検索、生成AIの活用は**すべて自由**とする。
- ただし、最終成果物として提出する「アプリのURL」および「GitHubリポジトリ」が、正しく本人のアカウントで構築・コミットされていることを評価基準とする。

### 🛠️ 実技試験の実施ステップ（生徒用手順）

#### Step 1：アプリのカスタマイズとGitHub Push
1. 教材用Railsアプリのリポジトリを、自身のGitHubアカウントへ **フォーク（Fork）** する。
2. Codespaces等で自分のフォークからクローンし、起動を確認する。
3. **【変更指示】** アプリケーションのトップページ（例：`app/views/articles/index.html.erb`）のヘッダーにあるタイトルを、**「（自分の名前）の本棚」** に書き換える。
4. 変更をコミットし、自分のリポジトリへ `push` する。

#### Step 2：AWSでのインフラ構築
1. 提供されたCloudFormationテンプレート（ `week12-baseline.yaml` ）をアップロードし、スタック（VPC, EC2 2台, ALB）を作成する。
2. RDS PostgreSQLインスタンス、DB Subnet Group、およびRDS用セキュリティグループを手動で作成・設定する。

#### Step 3：2台のEC2へのアプリデプロイ
1. 2台のEC2それぞれにSession Managerで接続する。
2. **自分自身のGitHubリポジトリ** からRailsアプリを `git clone` する。
3. 環境変数（`DATABASE_URL`, `SECRET_KEY_BASE`, `RAILS_ENV=production`）を設定する。
4. 1台目のEC2で `bin/rails db:prepare` を実行し、データベースをセットアップする。
5. 2台のEC2それぞれでアセットプリコンパイルを実行し、Railsをproductionモードでバックグラウンド起動（`-d`）する。
6. ALBのターゲットグループで、2台とも `Healthy` になることを確認する。

#### Step 4：成果物の提出
Googleフォームの解答欄に、以下の情報を貼り付けて送信しなさい。
1. **ALBのDNS名（URL）** （例：`http://rails-dojo-week12-alb-xxxxxx.us-east-1.elb.amazonaws.com`）
2. **自身のGitHubリポジトリのURL**
